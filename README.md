# santoku-docs

Documentation site for the santoku Lua framework, built with santoku itself: the pages are santoku templates, the styling is tailwind driven by the toku build, the server is the framework's standard nginx setup, and the interactive examples on the santoku tab run inside a Lua 5.1 interpreter compiled to WebAssembly by the santoku bundler. Pressing Run compiles the textarea contents with loadstring in the browser, captures everything printed, and shows the return values, so the docs demonstrate the framework by executing it. The framework targets Lua 5.1 as its permanent minimum baseline by design, with newer Lua versions meant to arrive as shims over the 5.1 core; the site states this position verbatim from a single field in content.lua. The `/llms.txt` and `/llms-full.txt` files are generated at build time from `client/lib/docs/content.lua`, so the crawler-facing text and the rendered tabs never drift.

To run locally you need `toku`, installed with `setup-toku.sh` from <https://santoku.dev> (the Install tab), plus the web toolchain that page's "Getting started: a web app" tab lists in full: openresty (both on PATH **and** named by `OPENRESTY_DIR`, which is the install prefix rather than the binary), emscripten (`emcc`/`emmake`, via emsdk), `node`, `openssl`, `curl` or `wget`, `librsvg2-bin` for `rsvg-convert`, and `tailwindcss` v4 (the build passes `--cwd`, which earlier versions do not accept; the v4 standalone binary works). The development loop is one command: `toku test --iterate` builds the test environment, starts the dev server, keeps it running, and rebuilds on file changes. It prints the URLs it is listening on, `https://localhost:8444` by default (the certificate is self-signed in dev); override with `PORT` and `SSL_PORT`. Leave it running while you edit. Scope a run to one test with `toku test --single <name>`. For one-shot, production-shaped runs: `toku build --test` then `toku start --test` builds and serves without watching, `toku test` runs the checks once, and `toku stop` shuts the server down.

Adding a tab's documentation: each documented library gets a module at `client/lib/docs/tabs/<name>.lua` returning `{ intro = ..., examples = { { title = ..., desc = ..., code = ... } } }`, kept loadable under plain system Lua (data only, no requires) because the llms.txt generator loads it at build time. Examples are runnable in the page by default; set `runnable = false` on any snippet that should render read-only (shell transcripts, code needing a filesystem or network, or modules not bundled into the page), and for runnable snippets add every module they require to `bundle_mods` in `make.common.lua` plus the owning rock to the client `dependencies`. Register the tab in `client/lib/docs/content.lua` by adding `content = require("docs.tabs.<name>")` to that library's row; rows without a content module automatically render the coming-soon stub.
